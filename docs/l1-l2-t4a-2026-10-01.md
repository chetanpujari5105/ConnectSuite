# L1/L2 T4-A — one byte corrupted in transit: the probe, the expected result, and the single hardware run (2026-10-01)

> **Status: preparation only.** The scoped probe and its tests are committed; **nothing was installed,
> armed, run or deleted, and no device command was issued.** The hardware run below needs the owner's
> approval. **T5 remains unapproved.**

## 1 · The decision

- **T4 is T4-A: corruption during transfer**, as in `docs/large-file-l1-l2-rules-2026-09-29.md` §6
  slice 3 — one byte flipped on the phone **after** it is hashed, so the Mac must name the failing block.
- **T4-B is a separate test, not a substitute:** a retained partial altered on the Mac while paused
  (rule S5). Nothing here plans or runs it.
- **T5 is not approved.**

## 2 · Why `FsProbeActivity` was undeclared, and what was kept

- **597cb75** (2026-09-22, the Sidekick UI pass) rewrote `app/src/debug/AndroidManifest.xml` and dropped
  every probe declaration, `FsProbeActivity` among them. The commit message does not mention it; the
  removal reads as incidental to adding `DesignPreviewActivity`.
- **The safety intent was recorded later**, in `docs/testing.md` → Feature A slice 3c (2026-09-24): the
  activity armed a **global** one-shot corruption of the next pull of **any** kind (Files, Photos, a Share
  pull without its own arm), and its comment claimed a debug-manifest entry it did not have. It was read,
  not exposed, and left undeclared.
- **What is kept:** there is no global switch any more (`BulkTransfers.debugCorruptAtByte` is deleted);
  the activity is debug-manifest-only and `DUMP`-gated like every adb harness since defect 152; and it
  refuses in a non-debuggable build.

## 3 · What the probe now is

`sync-module/…/FsCorruptionProbe.kt` (rules in `FsCorruptionArm`), armed only by
`app/src/debug/…/FsProbeActivity.kt`.

| Property | How it holds |
|---|---|
| One source | Fixed: root `downloads:connectsuite`, name `sidekick-pass-stop-200mb.bin`, size 209,715,200. The arm takes only a document id. |
| One byte | Fixed: offset **104,923,136** = zero-based block **800** of 1,600 (128 KiB blocks), 64 KiB in; XOR `0xFF` on one outgoing byte. The `at` extra of the old activity is refused. |
| One session | Arming records the one live, handshaken session; it refuses with none, with two, or with no token. |
| Bound before injection | `FsFeature.onBeginBlockPull` asks `FsCorruptionProbe.claim` before registering the transfer; the byte goes into that transfer's own `Pending` entry and the arm is consumed. |
| Nothing else affected | `claim` has one call site. Photos (`registerMediaPull`), small Files pulls (`registerFsPull`), Share pulls (their own scoped arm, unchanged) and pushes (`receiveFrom`) never ask. A replacement session is never bound. |
| Bounded | Expires after `ttlSec` (default 300 s, 10–600 s; out of range is refused, not clamped); `--ez disarm true`; cleared when its session ends; cleared when the approved file is requested in any other way (another session, size, name, block size, or any `resume`). |
| Fail-closed | Every refusal also clears an earlier arm. A claim in a non-debuggable build binds nothing. |
| Digests stay true | `BlockPullSender` hashes a chunk before the sink sees it; the flip is applied to the outgoing buffer, never the file. |

## 4 · Expected result, from the contract (§4, S8) and confirmed against today's code

Tests now pin each line (`FsCorruptionProbeTest`, `fsBlocks.test.ts`, `filesResume.test.ts` → *T4-A*):

1. **Block 800 reported.** Mac: `block 800 does not match what the phone read`, with **800** blocks
   verified (0–799). The phone's reported digests, manifest root and whole-file SHA-256 are of the true file.
2. **No final file.** `sidekick-pass-stop-200mb (7).bin` (the next free name today) is never created.
3. **Only this transfer's owned partial and resume record removed.** Any other paused pull's partial and
   record are untouched; a person's file at the name is untouched.
4. **A `.failed` marker** beside the free name: `sidekick-pass-stop-200mb (7).bin.failed`, text beginning
   `Sidekick transfer failed`. It is written exclusively (`wx`), so it never replaces anything.
5. **No automatic retry or resume.** The failure is not queued for reconnect resume; the phone is asked
   once.

**Existing behaviour to know (not changed):** `freeName` skips a name whose file or partial exists, but not
one whose `.failed` exists. If `… (7).bin.failed` were already present, `wx` would fail silently and **no
marker would be written** for this run. It is absent today; the preflight must re-check it.

Expected log lines: phone `[fs] PROBE ARMED (T4-A)…`, `[bulk] PROBE BOUND (T4-A): <id> …`,
`[bulk] PROBE: <id> byte 104923136 deliberately flipped…`, then most likely `block pull failed` once the Mac
has closed the socket (it depends on when the phone's next write fails, so it is not a pass criterion). Mac `[bulk] <id> not saved after N bytes: The file arrived damaged (block 800 does not match what
the phone read)…` with N ≥ 104,988,672 (the end of block 800; digests arrive in batches), and `[files] pull
of sidekick-pass-stop-200mb.bin did not finish: …`.

## 5 · The revised single hardware run (needs approval; nothing here has been done)

**Approval needed for:** one debug build and `install -r` on the SM-S938B, one arm, one pull. The Mac's
running build (`4095665`, `dist` `4c50a4d2…`) already has every Mac behaviour under test; this commit
changes no Mac runtime code (one comment in `main.ts`), so no Mac rebuild is needed.

1. **Install.** Build the debug APK from the commit; confirm `FsCorruptionProbe` is in its dex and the release
   merged manifest has no `FsProbeActivity`. `install -r` through `scripts/adb-pinned.sh samsung`. Start
   `MainActivity` by name; `scripts/link-up.sh` must give 3/3.
2. **Preflight (reads only), all recorded before arming:**
   - phone: source `_id=1000308768`, `sidekick-pass-stop-200mb.bin`, 209,715,200 B, SHA-256
     `bf375859…cbbec9`, its `date_modified`;
   - Mac: `fs.blocks: 1` negotiated; one live session; `pull-resume/` empty; ledger `[]`;
     `~/Downloads/Sidekick` listing with SHA-256 of every entry (50 today); **no** `… (7).bin`,
     `… (7).bin.sidekick-pull.part` or `… (7).bin.failed`.
3. **Arm, then pull within the TTL:**
   `scripts/adb-pinned.sh samsung shell am start -n com.chetan.connectsuite.debug/com.chetan.connectsuite.probe.FsProbeActivity --es docId 1000308768 --el ttlSec 300`.
   Proceed only on `ARMED (T4-A)` in logcat (`FsProbe`). Start **one** pull of that row from the Files
   pane's `Received files` root, by `data-id`, with the identity gate re-checked in the clicking expression.
4. **Pass** = all five lines of §4, plus the phone's `PROBE BOUND` naming the same transfer the Mac claimed.
5. **No reading (not a fail)** if `PROBE BOUND` never appears — the pull then ran uncorrupted, and the run says
   nothing about T4-A. Disarm and stop.
6. **After:** `--ez disarm true` (expected *"it was not armed"*); wait 60 s and confirm no second
   `fs.transfer.begin` and no new file; source SHA-256 and `date_modified` unchanged; the 50 pre-existing
   entries unchanged; `pull-resume/` empty; ledger `[]`.
7. **Left for the owner:** the `.failed` sidecar. Nothing is deleted without approval.

**What this run does not prove:** corruption on the wire (TLS 1.3 already rejects that; this exercises our
own write path, rule §0), T4-B, or T5.
