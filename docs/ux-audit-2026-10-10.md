# UX audit — 2026-10-10 (Mac and Android)

> **Status:** written during the UX-polish / speed / trial-design batch. Each finding carries its fix
> status; *fixed* means committed with a test that was shown red first, unless the row says otherwise.
> Evidence: `docs/evidence/ux-audit-2026-10-10/` (`mac-before/` — 104 JSON readings, one per shot,
> and the 26 shots at 1100×700 downscaled to 1×; the full 2× set of 104 was kept out of git for size; `android-before/` — the five tabs on the SM-S938B).

## 0 · Method, and the bounds of the instruments

**Skills applied.** `emil-design-eng`, `apple-design`, `review-animations` (its STANDARDS.md),
`improve-animations` (AUDIT.md, eight categories), `find-animation-opportunities` (the four-question
gate), `break-ui` (CATALOG.md) and, for the phone, `mobile-native` — **which mostly does not apply**:
it is about web apps in a mobile browser (100vh, tap highlight, input zoom, notch insets in CSS).
Sidekick for Android is native Compose, so only its general posture (*test on real hardware*,
*respect the system's text size*) carries over. `break-ui` was installed for this batch
(`9b56a0c`, pinned to upstream `e8a175d`, MIT, Markdown only, telemetry off during install).

**Mac instrument: `scripts/ux-sweep.mjs`.** Every pane × {1100×700 (the resize floor), 1440×900,
1920×1050 (the external display's work area), 1100×700 at View → Zoom In (917×583 CSS at dpr 2.4)}
× {dark, light}. **Emulated**, not real windows — the CSS layout is identical, the window chrome is
not; real-window checks on both displays are section 2's. The theme is stamped on `<html>` for each
shot and restored (the owner's appearance setting is never written). Per shot it reads:

- `offRight` — a visible control whose rect ends past the viewport's right edge;
- `clippedText` — an element with its own text, `scrollWidth > clientWidth`, overflow hidden and
  **no** ellipsis (cut with no sign anything is missing). An ellipsis is a decision, not counted;
- `pageHScroll` — the page wider than the viewport.

**Its first run had a lookalike, caught before it became a finding:** 49 `clippedText` hits on
Messages were all `.visually-hidden` screen-reader text, which is clipped to 1 px on purpose. The
instrument now skips it and says so in its header.

**Android instrument:** `adb exec-out screencap` through `scripts/adb-pinned.sh`, tabs reached by
tapping the node whose visible text is the tab name (refusing on 0 or 2 matches — the icon and the
label both carry the name as content-desc and text). One phone (SM-S938B, 1440×3120, 600 dpi).

## 2 · Motion — what held up

`improve-animations`' eight categories, read against `tokens.css`, `shell.css`, `styles.css`,
`float.css`, `share-window.css` and the Android `Motion` object (`core/.../ui/SidekickDimens.kt`):

| Category | Mac | Android |
|---|---|---|
| Purpose & frequency | route change is **140 ms opacity only** (`--dur-route-fade`, N-M2 cut it from ~410 ms); the ⌘K palette has **no** open animation | screen changes use `ROUTE_MS` 260 |
| Easing & duration | every transition reads a token; `check-motion-tokens.mjs` refuses a raw duration. **0** `ease-in`, **0** `transition: all`, **0** UI transitions over 300 ms (the only longer values are a spinner turn, a one-off deep-link flash and a 6 s ambient brand glow, all off under reduced motion) | `Motion.ease` / `easeInOut` are the same two curves |
| Physicality | press scale 0.97 (`--press-scale`), icons 0.94; press 100 ms, release 160 ms — asymmetric the right way | `PRESS_SCALE` 0.97, same asymmetry |
| Interruptibility | transitions, not keyframes, on everything rapid | `animate*AsState` (retargets) |
| Performance | transform and opacity only (`tokens.css` motion header) | — |
| Accessibility | `prefers-reduced-motion` blocks in tokens, shell, styles and float; spinners freeze, words carry the state | Compose follows the system animator scale |
| Cohesion | one token family across both apps | ported from the Mac's tokens |
| Missed opportunities | see below | — |

**`find-animation-opportunities`: nothing survived the gate.** Candidates considered and rejected:
a fade on Files rows as a page loads (tens of times a day, and the list is data being read — *Function*
gate); a slide on the status island (100+ times a day — *Frequency*); a stagger on the Apps grid
(occasional, but a 122-icon grid staggering is decoration on a launcher — *Function*). The motion
system is restrained on purpose, and this batch keeps it that way.
